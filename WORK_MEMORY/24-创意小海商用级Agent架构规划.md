# 创意小海商用级 Agent 平台架构规划

> 记录时间：2026-05-04

---

## 三层架构目标

### A. 架构层：跨模块贯通
- A1：三层记忆（Global/User/Task）贯通
- A2：模块标准化工具接口（MCP协议方向）
- A3：主动推荐引擎（跨模块智能匹配）

### B. 交互层：Chat 内透明化
- B1：工具调用透明化（工具名→进度→结果卡片）
- B2：内嵌任务进度（状态卡片在聊天流中）
- B3：跨模块推荐卡片（学习库/模板/素材主动推荐）

### C. 连续性层：断点重续
- C1：会话断点感知（"你有1个进行中的任务"）
- C2：跨会话任务统一管理
- C3：失败智能恢复（原因+重试+替代方案）

## 当前 UI 渲染完善度分析（2026-05-04）

### 内容类型渲染状态

| 内容类型 | 当前渲染 | 问题 | 缺失的行动入口 |
|---------|---------|------|-------------|
| 视频分析卡片 | `cardType: 'video_analysis'` 紧凑文字 | 无后续行动 | 无"基于此风格生成脚本"按钮 |
| 脚本表格 | 通用 `table` Part | 无脚本专用设计，多脚本平铺无对比 | **"选这个"/"修改"/"对比查看"按钮** |
| 首帧图 | `max-w-[320px]` 固定尺寸 `<a>` 链接 | 硬编码尺寸，无加载态 | **"生成视频"/"重新生成"按钮** |
| 任务提交确认 | `cardType: 'task_submitted'` 文字 | 无进度信息 | 无"视频生成中..."实时状态卡片 |
| 视频结果 | `<video>` 播放器 380x280 | 硬编码尺寸，无交互按钮 | **"下载"/"分享"/"存学习库"/"生成配文"** |
| 通用 tool_result 卡片 | 显示工具名+状态+task_id | 信息过载 | 无上下文相关行动建议 |

### 核心结论
当前 UI 是**信息终点**模式——每个卡片只展示内容，不推进工作流。
目标：改为**决策点**模式——每个卡片展示结果 + 1-3个行动按钮，用户点击即进入下一步。

### 工具连续性（Tool Continuity）

当前机制：
```
工具结果 → 伪装为 user 消息注入 LLM messages 数组 → LLM 继续生成回复
```

问题：
- 系统提示词有"主动推动下一步"的原则性指导，但LLM行为不可靠
- 异步完成的工具（submit_video_task）结果通过通知表走，不进LLM对话
- 视频完成后没有自动"注入对话"的机制

### 需改造的组件清单

1. **ScriptCard**（新）：专用脚本卡片，含表格 + 行动按钮
2. **FirstFrameCard**（新）：首帧图卡片，大图 + 确认/重生成
3. **VideoResultCard**（新）：视频结果卡片，播放器 + 下载/分享/存库
4. **TaskProgressCard**（新）：任务进度卡片，chat内嵌显示状态
5. **AnalysisCard**（改造）：视频分析卡片，追加"基于此风格创作"按钮
6. **ToolResultCard**（改造）：通用工具结果，上下文相关行动建议
