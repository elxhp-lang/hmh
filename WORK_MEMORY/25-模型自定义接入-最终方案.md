# 模型自定义接入 — 最终方案（含子Agent定义）

> 2026-05-06 | 状态：待确认

---

## 零、核心原理

**插件式语义适配器。** 子Agent 理解工具需要什么、新模型提供什么，自动生成适配函数。适配器存入数据库，运行时动态加载。不修改源码文件。

```
工具需要的输出:   {task_id, status, video_url} 写入 videos 表
用户提供代码返回: {id, state, result.url}
↓ 子Agent语义匹配 ↓
适配器:   adapter.getTask = (id) => fetch(...).then(r => ({status: r.state, video_url: r.result.url}))
```

**适配器只替换 2 个调用点。** 轮询器、查询工具、任务栏、对话注入不碰——它们通过数据库表联动，不依赖模型API。

## 一、子Agent 定义

### 它是什么

一个有特定工具集的 LLM 实例，和创意小海底层相同但**完全隔离**——不同路由、不同提示词、不同工具、不存对话历史。

| 维度 | 创意小海 | 子Agent |
|------|---------|--------|
| 路由 | `/api/xiaohai/agent/chat` | `/api/models/*` 内部调用，不暴露 |
| 系统提示词 | `xiaohai-system-prompt-v3.ts` | 模型配置专用提示词（内联在 model-config-agent.ts） |
| 工具集 | 24个视频创作工具 | analyze_code / test_endpoint / generate_adapter / check_db_schema |
| 上下文 | 用户对话历史 | api_example + MODEL_DEPS + audit_result |
| 对话存储 | agent_conversation_messages | 配置对话框中，不持久化 |
| 触发方式 | 用户发消息 | 保存模型 / 点击测试 / 配置对话框交互 |
| 运行模型 | 用户选的主Agent模型 | 同主Agent，不可用→Coze默认兜底→报错 |

### 工具集

| 工具 | 作用 | 实际执行方式 |
|------|------|------------|
| `analyze_code` | 读用户 api_example → 提取端点/认证/请求体/响应体结构 | LLM文本理解（不调HTTP） |
| `match_fields` | 新模型字段名 ↔ 系统标准字段名 语义匹配 | LLM语义推理 |
| `test_endpoint` | 实际 HTTP 调用，测连通性 | fetch + 返回原始响应文本 |
| `generate_adapter` | 生成适配器 JS 代码字符串 | LLM 代码生成 |
| `check_db_schema` | 读 information_schema 验证表列名 | supabase 查询 |
| `run_pipeline` | 按 model-deps 逐项测试全链路 | 调 test_endpoint + 写 TOS + 写 DB |

### 调用时机

| 触发 | 调子Agent做什么 | 写什么到数据库 |
|------|---------------|--------------|
| **保存模型** | analyze_code → match_fields | audit_result.fields + caps |
| **点"测试连通"** | generate_adapter → run_pipeline 逐项 | audit_result.adapter + tests, status |
| **测试有失败** | 解读错误 → 给建议 | 对话框内交互，不写DB |

## 二、数据层

### user_models 表字段（完整）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | PK |
| user_id | uuid FK | users.id |
| alias | varchar(100) | 用户自定义名称 |
| model_type | varchar(20) | chat / image / video |
| api_url | text | API 端点 |
| api_key_encrypted | text | AES-256-GCM 加密 |
| model_name | varchar(200) | 如 deepseek-v3 |
| api_example | text | **新增**：用户粘贴的标准调用代码 |
| audit_result | jsonb | **新增**：子Agent标注+测试结果+适配器 |
| is_default | boolean | 默认模型 |
| auto_fallback | boolean | 不可用时回退默认 |
| status | varchar(20) | untested / ok / partial / incompatible |
| last_tested_at | timestamptz | 最后连通测试时间 |
| created_at / updated_at | timestamptz | 时间戳 |

### audit_result 结构

```json
{
  "fields": {
    "createTask": { "input": {"prompt": "...", "duration": "..."}, "output": {"task_id": "..."} },
    "getTask":    { "output": {"status": "...", "video_url": "..."} }
  },
  "caps": {
    "multi_modal": true,
    "reference_video": true,
    "reference_audio": false,
    "max_duration": 10
  },
  "tests": {
    "create": "ok",
    "poll": "ok",
    "download": "ok",
    "tos_upload": "ok",
    "inject": "ok"
  },
  "adapter": "module.exports = { createTask: async (p) => { ... }, getTask: async (id) => { ... } };"
}
```

## 三、依赖映射表（model-deps.ts）

纯数据文件，子Agent 用它了解"工具需要什么"——硬校验，防幻觉。

```typescript
export const MODEL_DEPS = {
  image: {
    label: '图片生成',
    requiredOutputs: ['image_url'],
    pipeline: [
      { id: 'generate',    desc: '调生成端点 → 返回 image_url' },
      { id: 'download',    desc: 'fetch image_url → 二进制图片' },
      { id: 'tos_upload',  desc: '上传 TOS → 返回 public_url' },
      { id: 'inject',      desc: 'public_url 写入 agent_conversation_messages' },
    ],
  },
  video: {
    label: '视频生成',
    requiredOutputs: {
      createTask: ['task_id'],
      getTask: ['status', 'video_url'],
    },
    pipeline: [
      { id: 'submit',         desc: '调创建端点 → 返回 task_id' },
      { id: 'poll',           desc: '调查询端点 → 返回 status + video_url' },
      { id: 'download_video', desc: 'fetch video_url → TOS 上传' },
      { id: 'inject',         desc: 'public_url 写入 agent_conversation_messages' },
      { id: 'task_update',    desc: 'worker_tasks 状态流转 running→succeeded' },
    ],
  },
} as const;
```

## 四、配置流程

```
1. 用户打开 /settings/models/add
   → 填表：别名、类型(image/video)、URL、Key、模型名、调用代码
   → 保存 → 后端调子Agent → analyze_code + match_fields → 写 audit_result

2. 模型出现在 /settings/models 列表，状态=untested 或 partial
   → 用户点"测试连通"
   → 后端调子Agent → generate_adapter → run_pipeline 逐项测试
   → 全部通过: status='ok', 适配器可用
   → 有失败: 配置对话框打开

3. 配置对话框（页面内嵌）
   ┌──────────────────────────────────────────┐
   │ 子Agent: 3/5 通过。                      │
   │ ⚠️ 该模型不支持多模态参考视频              │
   │ ❌ 轮询返回字段无 video_url               │
   │ 请提供轮询返回示例或说明如何获取视频URL：   │
   │ ┌──────────────────────────────────────┐ │
   │ │ [用户输入框，可粘贴代码或说明]         │ │
   │ └──────────────────────────────────────┘ │
   │ [重新测试] [跳过]                         │
   └──────────────────────────────────────────┘
   可多轮对话，直到全部通过或用户放弃

4. status='ok' → 模型在选择器中可用
   caps 有缺失 → 选择器旁标注"不支持视频生视频"
```

## 七、运行时加载

```
工具调用 → 读用户选择的 modelId
  → modelId 存在 → 读 audit_result.adapter
    → adapter 存在 → 加载 → 替换默认 createTask/getTask
    → adapter 不存在 → 系统默认
  → modelId 不存在 → 系统默认
```

适配器通过 `new Function()` 在受限作用域中执行，仅暴露 `fetch` 和上层 TOS 存储函数，不暴露 `fs`、数据库写入、`process.env`。

适配器抛错 → 自动降级系统默认 + 打日志。

## 九、全维度自审

| 维度 | 状态 | 说明 |
|------|------|------|
| 架构 | ✅ | 不改现有架构，适配器是数据不是代码 |
| 安全 | ✅ | 适配器沙箱执行，仅暴露 fetch；api_key 加密存储 |
| 数据流 | ✅ | 适配器输出固定格式，下游不感知 |
| 前端 | ✅ | 未连通模型不显示，降级模型标注 |
| 认证 | ✅ | 不需要额外认证机制 |
| 运行时 | ✅ | 适配器出错自动降级默认 |
| 交付 | ✅ | 三库迁移，新增2个页面，无破坏性变更 |
| 隔离 | ✅ | 用户A的适配器用户B不可见（user_id过滤） |

### 已知风险

| 风险 | 缓解 |
|------|------|
| 子Agent 语义标注不准 | MODEL_DEPS 硬校验兜底；测试全部通过才生效 |
| 适配器执行时出错 | try/catch → 日志 → 降级默认 |
| 用户编辑 api_example 后适配器过期 | 编辑后 status 重置为 untested，需重新测试 |
| 删除正在使用的模型 | 自动回退系统默认 |
| 视频模型切换后历史任务状态错乱 | 不追溯——已创建的任务继续用原模型轮询 |
